# functions/

## Rôle
L'API, sous forme de Cloudflare Pages Functions. Runtime Workers : ce n'est **pas** Node.
Ce dossier doit rester à la racine du dépôt, sinon Cloudflare ne le détecte pas.

## Contenu
types.ts       — les liaisons (D1, secrets VAPID) et le contexte, déclarés une seule fois
_middleware.ts — authentification par clé, en-têtes de sécurité, CSP
api/           — une route par fichier

## Conventions
- Une route = un fichier, dont le chemin donne l'URL (`api/ask.ts` → `/api/ask`).
- Chaque fichier exporte `onRequestGet` ou `onRequestPost`, pas les deux.
- L'authentification est faite par le middleware et dépose l'utilisateur dans `data.user`.
  Une route ne relit jamais l'en-tête `Authorization`.
- Toutes les réponses sont en JSON, même les erreurs : `{ error: 'code' }`.
- L'envoi d'un push est **toujours** différé dans `ctx.waitUntil()`. Une notification qui
  échoue ne doit jamais faire échouer l'écriture du message.

## Dépendances
Peut importer : les utilitaires locaux de `functions/`.
Ne doit jamais importer : quoi que ce soit de `src/` (code navigateur), ni un module Node.
Écrit dans D1 via le binding `env.DB`.

## Pièges
- Aucun module Node : ni `crypto`, ni `buffer`, ni `fs`. On utilise `crypto.subtle`,
  `TextEncoder` et les API web.
- `web-push` (npm) **ne fonctionne pas ici**. Le protocole est implémenté à la main sur
  WebCrypto : JWT ES256 pour VAPID, chiffrement aes128gcm pour la charge utile.
- D1 est du SQLite : pas de booléens (0/1), pas de `NOW()`, dates en entiers.
- Une réponse 404 ou 410 d'un service de push signifie que l'abonnement est mort : le
  supprimer immédiatement, sinon la table se remplit d'endpoints fantômes.
- Le middleware tourne AUSSI sur les fichiers statiques : il faut filtrer explicitement sur
  `/api/`, sinon servir une police demanderait une clé.
- Les limites de `api/_limits.ts` doublent celles de `src/lib/config.ts`. C'est voulu — les
  deux environnements ne s'importent pas — mais elles doivent bouger ensemble.
